# TailscaleCraft

Открытый проект для запуска Minecraft Java + Bedrock на **своём Windows-ПК через свой Tailscale**. Каждый владелец скачивает одну и ту же копию исходников, включает свой Tailscale и получает адрес собственного сервера. Адрес автора, ник автора и пути его компьютера не используются.

Исходники распространяются под MIT. Серверные компоненты скачиваются отдельно из официальных источников с проверкой SHA256. Архив исходников не содержит миров, ключей, аккаунтов или лицензированной копии Minecraft.

Пошаговая инструкция для владельца, друзей на телефонах и игроков Java: **[CONNECT.md](CONNECT.md)**. В GitHub исходники скачиваются через **Code → Download ZIP**.

## Быстрый запуск

1. Скачайте архив проекта и распакуйте в обычную папку, в которую у вас есть право записи, например `Documents/TailscaleCraft`. Запуск внутри ZIP не поддерживается.
2. Установите [Tailscale](https://tailscale.com/download) на ПК и подключите его к **своему** аккаунту. На телефонах друзей тоже нужен Tailscale.
3. Дважды нажмите **START.cmd**. При первом запуске загрузятся Paper, Geyser, Floodgate, ViaVersion и, если нужно, переносимая Java 25. Нужен доступ к интернету. Системная Java не заменяется.
4. Прочитайте Minecraft EULA. Введите `YES`, только если принимаете её. Каждый владелец принимает условия самостоятельно.
5. Дождитесь `Done`. В окне будут показаны актуальные адрес и порты вашего сервера. Java подключается к показанному адресу с портом **25565**, Minecraft на телефоне — с портом **19132**.
6. Один раз запустите **FIREWALL.cmd** через правую кнопку → «Запуск от имени администратора», если брандмауэр блокирует подключения. Правила разрешают игровые порты только на текущем IPv4-адресе Tailscale и для источников из сети Tailscale.

Для обычного запуска права администратора не нужны. Если сеть Tailscale выключена, программа объясняет причину и прекращает запуск. При следующем запуске новый адрес определяется автоматически; после изменения адреса повторите FIREWALL.cmd.

## Как друзья получают доступ

Если устройства друзей уже подключены к вашей сети Tailscale, используйте её правила доступа. Иначе откройте [Machines](https://login.tailscale.com/admin/machines), выберите свой ПК → **Share** и создайте ссылку приглашения. Друзья принимают её под собственными Tailscale-аккаунтами. Передавать им пароль вашего аккаунта не требуется. [Документация Tailscale](https://tailscale.com/kb/1084/sharing).

Каждый друг включает Tailscale на телефоне, затем открывает Minecraft → «Играть» → «Серверы» → «Добавить сервер», вводит показанный владельцу IP и Bedrock-порт. Автоматическое обнаружение мира по LAN не требуется.

Белый список Minecraft **отключён**. Регистрировать игровые ники не нужно. Java допускает вход по нику. Для Bedrock доступны два режима, описанные ниже. Доступ к ПК ограничивается вашей сетью Tailscale и её правилами; конкретные аккаунты или ACL программа не изменяет. Каждый запускает свой независимый сервер и свой мир.

## Bedrock с аккаунтом и без: экспериментальный режим

В `config.json` параметр `allowOfflineBedrock: true` включает `java.auth-type: offline` и `advanced.bedrock.validate-bedrock-login: false` в Geyser. Это отключает серверную проверку Xbox-аккаунта для всех Bedrock-подключений, включая клиентов, уже вошедших в Microsoft-аккаунт. Проверенный вход и вход без проверки не разделяются на этом порту.

Это **экспериментальная настройка, а не гарантия входа с любого телефона**. Geyser официально не поддерживает её для обычных офлайн-клиентов. Некоторые гостевые форматы входа всё равно отклоняются; сам Minecraft может требовать Microsoft-аккаунт до подключения. Серверный параметр не меняет приложение на телефоне. В проверенной установке телефон с Microsoft-аккаунтом подключился, а телефон без аккаунта получил ошибку Guardian даже с этой настройкой. Не рассчитывайте на неё как на рабочий гостевой вход.

Для возврата к обычному Floodgate-входу задайте `allowOfflineBedrock: false` и перезапустите сервер. В таком режиме Bedrock требует Microsoft/Xbox-аккаунт, но Java Edition покупать не нужно.

В экспериментальном режиме ник не подтверждается, а Floodgate-скины и привязка аккаунтов не используются. Участник вашей сети может указать чужой ник, включая ник администратора. Оставляйте доступ к ПК только доверенным друзьям и учитывайте это перед выдачей `op`. При смене режима идентификаторы игроков могут измениться: инвентарь и местоположение могут выглядеть как у нового игрока. Перед переключением остановите сервер и сделайте BACKUP.cmd.

## Требования и версии

- Windows 10/11, PowerShell 5.1+, доступ к интернету для установки. Автоматическая загрузка Java рассчитана на Windows x64.
- Подключённый Tailscale. Java 25 находится через JAVA_HOME/PATH либо скачивается в `runtime/`.
- В этой версии закреплены Paper 26.2 build 133, Geyser 2.11.3 build 1251, Floodgate 2.2.5 build 141 и ViaVersion 5.12.1.
- Основной Java-клиент — 26.2; ViaVersion добавляет поддержку 26.3. Forge-клиент без обязательных серверных модов может подключаться; при проблемах используйте обычную Java 26.2.
- На момент подготовки Geyser поддерживает Bedrock 26.30–26.52, включая 26.51.1. [Поддерживаемые версии Geyser](https://geysermc.org/wiki/geyser/supported-versions/). Более новые версии телефонов могут потребовать обновления зависимостей.

## Настройки и команды

| Файл | Действие |
| --- | --- |
| START.cmd | Проверить сеть, подготовить сервер и запустить |
| SETUP.cmd | Скачать и проверить компоненты без запуска игры |
| CHECK.cmd | Показать состояние Tailscale, Java и установки |
| FIREWALL.cmd | Настроить игровые порты; требует администратора |
| BACKUP.cmd | Создать ZIP-копию остановленного сервера |

В `config.json` меняются порты, память, число игроков и название сервера. По умолчанию серверу доступно до 4 ГБ RAM. Для ПК с небольшим объёмом памяти поставьте 2–3. Название MOTD в этой версии задаётся печатными ASCII-символами.

`viewDistance` задаёт максимальную дальность отправки чанков сервером (по умолчанию 6), `simulationDistance` — дальность симуляции мира (по умолчанию 4). Допустимы значения 2–32. Для снижения нагрузки и объёма передаваемых данных можно уменьшать их; это также сокращает область активности мобов и ферм. Эти серверные настройки применяются при запуске. Графику и FPS телефона они напрямую не настраивают. Если параметры телефона недоступны, выйдите из сервера и проверьте раздел видео в главном меню; настройка симуляции чужого сервера выполняется владельцем сервера.

Geyser передаёт запрошенную телефоном дальность Java-серверу, но серверный предел остаётся: [обработчик дальности Geyser](https://github.com/GeyserMC/Geyser/blob/master/core/src/main/java/org/geysermc/geyser/translator/protocol/bedrock/BedrockRequestChunkRadiusTranslator.java), [параметры Paper](https://docs.papermc.io/paper/reference/server-properties/). Обычным конфигом нельзя разблокировать ползунки приложения или дать каждому телефону произвольную симуляцию мира. Проверка откатов далёких блоков и команды изменения дальности взаимодействия описаны в [CONNECT.md](CONNECT.md#дальность-и-откаты-блоков).

Можно создать `config.local.json` только с личными изменениями, например `{"memoryGB": 2}`. Он исключён из Git и исходного архива.

`bedrockMtu` по умолчанию равен 1200 байтам, чтобы пакеты Bedrock помещались в интерфейс Tailscale с MTU 1280 с учётом заголовков. Допустимы значения 576–1400. Это уменьшает риск фрагментации, но не гарантирует устранение сетевых задержек. Проверка результата выполняется на реальном телефоне после перезапуска сервера.

Миры и настройки находятся в `server/`. Для остановки в консоли введите **stop** и дождитесь сохранения. Настройки сети и отсутствие белого списка применяются при каждом запуске; остальные параметры server.properties и Geyser сохраняются.

## Дополнения

Этот проект использует **Paper-плагины**, которые устанавливаются в `server/plugins/`. Он не запускает произвольные Forge-сборки. Моды, требующие установки на каждом клиенте и добавляющие новые блоки или предметы, обычно несовместимы с подключением Bedrock через Geyser. [Ограничения Geyser](https://geysermc.org/wiki/geyser/faq/).

Перед добавлением плагина остановите сервер, сделайте BACKUP.cmd, добавьте один плагин для Paper 26.2 и проверьте Java и телефон. Универсальной гарантии совместимости всех дополнений нет.

## Если не подключается

- Запустите CHECK.cmd. Tailscale на ПК и телефоне должен быть подключён; друг должен принять приглашение к этому ПК.
- Используйте IP из текущего окна запуска, а не IP прежнего владельца архива. В телефоне порт указывается отдельно.
- Проверьте FIREWALL.cmd и собственные ACL Tailscale: UDP Bedrock-порта и TCP Java-порта должны быть разрешены.
- При `allowOfflineBedrock: false` вход в Microsoft/Xbox на телефоне нужен для Floodgate. При `true` сервер его не проверяет, но сам клиент может требовать вход. Ограничения семейного аккаунта Minecraft могут запрещать многопользовательскую игру.
- Проверьте `server/logs/latest.log`. Не запускайте две копии сервера на одних портах.
- При ошибке SHA256 не обходите проверку: проверьте загрузку и официальную контрольную сумму. Существующий файл с неверной суммой автоматически не заменяется.

## Разработка и распространение

`scripts/common.ps1` содержит обнаружение сети/Java, загрузку и настройку. `scripts/manage.ps1` отвечает за команды. `dependencies.json` закрепляет компоненты; автоматического обновления на несовместимые версии нет.

Проверка конфигурации без сети и скачиваний:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\test-config.ps1
```

Проверка запуска с уже скачанными компонентами (создаёт отдельный тестовый мир):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tests\smoke-server.ps1 -JavaPath "C:\path\to\java.exe" -ExistingServer "C:\path\to\server" -AcceptEula
```

Используйте `-AcceptEula` только после принятия условий. Проверка проверяет Java status, Bedrock UDP ping и корректное сохранение при остановке. Вход реального телефона через другую сеть проверяется отдельно.

Создание чистого архива:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package.ps1
```

Полученный `dist/TailscaleCraft-source.zip` можно передать друзьям или приложить к GitHub Releases. Упаковка использует явный список файлов: `server/`, `runtime/`, `backups/` и личные настройки туда не входят. В Git публикуются только исходники этого каталога с учётом `.gitignore`; установленные компоненты и мир каждого владельца создаются локально.

Лицензии зависимостей описаны в [THIRD-PARTY.md](THIRD-PARTY.md).
